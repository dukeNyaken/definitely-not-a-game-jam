## Исправлено в этой ветке (воспроизведены и покрыты тестами)

### 1. Святилище остаётся активным после таймаута — `scripts/game/game.gd` (State.SHRINE)
**Воспроизведение:** этап 3/5 → не наступать на святилище 15 с → 3-я волна начинается → наступить посреди боя → пауза и обмен кольца во время боя. `_on_shrine_stepped()` проверял только `shrine_used`, а таймаут не выставлял его и не убирал узел.
**Фикс:** `shrine_done(false)` перед `start_wave(wave + 1)`. Согласуется с DESIGN.md: «отказ убирает святилище до конца этапа» — таймаут теперь делает то же.

### 2. Битый `data/item_mastery.json` убивал всю мета-прогрессию — `scripts/autoload/item_mastery.gd`
**Воспроизведение:** некорректный JSON → `JSON.parse_string` вернул `nil` → присвоение в типизированный `Dictionary` не прошло → каскад ошибок `Invalid access … 'thresholds'` на каждом обращении (XP, уровни, формы, UI).
**Фикс:** загрузка правил в `_ready()` через `_load_rules()` с `_rules_valid()` (пороги: ровно 3, возрастают; все 7 вещей описаны). При битых данных — `push_error` один раз и деградированный режим: `level()` → 1, `form()` → базовая вещь без изменений, XP без капа. Все потребители (`level`, `form`, `reward`, `award`, `progress_text`, `load_progress`) переведены на безопасные `.get()`.

### 3. Краш `_speeds[1]` в анимации ходьбы — `scripts/visual/skinned_actor_model.gd` (`_animate`)
**Воспроизведение:** все ходовые клипы замера отброшены фильтром немонотонности (в логе регулярно виды: «Sprint не быстрее предыдущего клипа — пропущен», например `npc_jester.json`) → `_speeds.size() < 2` → `Index out of bounds` каждый кадр при движении.
**Фикс:** guard `_speeds.size() >= 2`, ближайший клип ищется с индекса 0. При <2 валидных клипов актор играет idle — разумный фолбэк.

### 4. `RunState.sacrifice/swap` без валидации индекса — `scripts/autoload/run_state.gd`
Публичный API падал на `index = -1` (реальный путь: `theater.gd` → `index_of()` → `-1` при рассинхроне каталога и кольца). Добавлены guard'ы с `push_error` и ранним возвратом.

### Заметки (устойчивость и краевые случаи)

**6. Диск-I/O на каждом убийстве — `item_mastery.gd: award()`.** `save_progress()` (~3 файловые операции: `.tmp` + `.bak` + rename) и `changed.emit()` на каждой смерти врага от руки героя; рой — десятки записей за волну. Риск: попадание rename на антивирус/индексацию → ложный баннер «Не удалось сохранить». Рекомендация: дебаунс (не чаще раза в 2-3 с) + гарантированный сейв на жертве/финиже забега/выходе в меню; пропускать save при пустом `hero.items`.

**7. Подсветка на трупе босса — `skinned_actor_model.gd: _on_died`.** Не вызывает `super` и не снимает `material_overlay`: босс, умерший в окне уязвимости (фиолетовый оверлей) или по криту (flash), навсегда останется цветным. Лечится циклом снятия оверлея или вызовом `super._on_died()`.

**8. Двойной `_next_stage` при отладочном пропуске — `game.gd: do_sacrifice (488) + debug_skip_stage (510-522)`.** F1 → «Пропустить этап» в окне 2.4 с до отложенного перехода → этап перескочит на +2. Заодно: массовый `die()` в `debug_skip_stage` рождает живых слизнёнышей (`_split`), этап «пройден» при живых врагах. Debug-only, фиксится флагом-подавлением.

**9. Оглушение не прерывает рывок — `actor.gd: stun() vs _physics_process()`.** `dash_time/dash_velocity` не сбрасываются; ветка рывка идёт раньше проверок `can_act()`. Оглушённая элита с сапогами долетит рывок до конца. Если не задумано — сбрасывать `dash_time` в `stun()`.

**10. Утечка узла `Shockwave` — `amulet_action.gd:16-19`.** При `Vfx.root_for(actor) == null` узел создан, но не добавлен и не освобождён (Node не RefCounted). Редко, но `else: wave.queue_free()` дешевле.

**11. Хардкод «/ 7» вместо `Db.balance.stage_count`** — `final_card.gd:54`, `hud.gd:200/203`. Смена числа этапов в балансе сделает итоговый экран врать.

**12. `final_card.gd:212` — `Mastery.rules["thresholds"][i]` без защиты** (и `mastery_ui.gd`/`final_card.gd` литеральные `thresholds[1]/[2]`). После фикса №2 не падает при валидном JSON, но при расширении числа тиров сломается. Стоит брать пороги через `rules.get("thresholds", [])` с guard'ом.
